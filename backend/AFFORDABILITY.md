# INR affordability assessment

The Flutter app sends `currency: INR` and `loan_term_months` to `/predict`.
Amounts entered are rupees, not converted historical dollar amounts.

Monthly income = annual income / 12. Existing monthly debt is estimated as
monthly income * existing DTI / 100. The existing DTI must exclude the new loan.
The new EMI uses the reducing-balance formula with annual interest / 1200 as
the monthly rate. At zero interest, EMI = principal / term.

The assessment compares (existing debt + new EMI) / monthly income against
the configurable demo threshold, inclusive. The default is 40%. This is a
project assumption, not an Indian lender or regulatory standard. Fees and
living expenses are excluded. It is not an approval decision.

To configure in Windows cmd before starting the backend:

```cmd
set AFFORDABILITY_DTI_LIMIT_PERCENT=40
venv\Scripts\python.exe app.py
```

INR applications use a separate synthetic demo model generated by
`venv\Scripts\python.exe train_inr_demo.py`. The original repayment model is
not used for INR. No exchange rate is guessed. Original requests without
currency retain the legacy model behavior.

The synthetic model predicts invented demo approval labels. The exact label
formula, held-out synthetic evaluation, and limitations are recorded in
training/inr_demo_report.json. training/synthetic_inr.csv preserves the data
and split. No real Indian borrower data is used; INR is an explicit simulation
unit. The model is not validated for actual bank approvals or fairness.
Gender, marital status, employment and education do not affect its output.
The score uses total debt including EMI, credit score, and log income.

Missing or out-of-range model inputs produce an unavailable score while the
affordability calculation continues. See RANGES in inr_demo_model.py.
Restart the backend after retraining to reload its cached model.

INR results are stored separately in `affordability_assessments`, preserving
existing prediction records. `/history` includes `affordability_history`.
`LENDIQ_DB_PATH` can isolate a test database.

The payment examples page calculates illustrative INR payments from the
requested amount and rate; it does not display lender offers or simulate
money transfers.

Run backend checks: `venv\Scripts\python.exe -m unittest discover -v`.
Run frontend checks from flutter_app: `flutter analyze` and `flutter test`.
